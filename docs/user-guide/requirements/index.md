# Requirements

Requirements are the core unit of work in IR-Board. Every requirement is either **functional** (what the system must do) or **non-functional** (a measurable quality constraint, such as a performance or reliability threshold), and both share a common lifecycle, identifier scheme, and set of traceability mechanisms.

- **[Functional Requirements](functional-requirements.md)** — creating, nesting, and reordering requirements scoped to a functionality.
- **[Non-Functional Requirements](non-functional-requirements.md)** — defining measurable quality constraints at the project level.
- **[Linking and Traceability](linking-and-traceability.md)** — connecting requirements to stakeholders, documents, and each other, and finding entities by their identity slug.
- **[Requirement Lifecycle](requirement-lifecycle.md)** — the states a requirement moves through, approval, and how changes propagate as review flags.

Before working through this section, it helps to have at least one [project](../projects/index.md) and, for functional requirements, a [functionality](../projects/functionalities.md) to work within.
